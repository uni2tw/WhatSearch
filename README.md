# WhatSearch

一個給朋友用的個人 FTP 空間瀏覽/搜尋小工具：設定要分享的目錄後，朋友就能透過網頁搜尋、瀏覽、播放裡面的檔案，不用整包下載也不用翻 FTP 目錄。

## 功能

### 檔案瀏覽 / 搜尋
- 逐層瀏覽分享目錄，支援鍵盤方向鍵選取、Enter/→ 進入、← 回上層
- 檔名全文搜尋（Lucene.Net 索引），搜尋前會把簡體轉成繁體再比對
- 快速篩選 chip：只看音樂／只看影片／只看圖片
- 「最近上傳」聚合列表，跨資料夾依上傳時間排序
- 列表每一列的影片會顯示長度（例如 `24:10`、`2:00:00`）：由伺服器讀取 MP4（TagLibSharp）與 MKV（自行解析）的長度，結果依「路徑＋大小＋修改時間」快取；單一資料夾最多讀前 50 部、平行 4 個，讀不到（格式不支援、檔案損毀）就不顯示，不影響列表。搜尋與「最近上傳」的結果不含長度
- 搜尋 0 筆結果時提供「回瀏覽模式」引導按鈕
- 搜尋輸入模式支援按 ESC 或點空白處退出
- 路徑（麵包屑）每一層是 40px 高的膠囊按鈕（好點、有按壓回饋），目前所在的資料夾為外框樣式、不可點；層與層之間在桌機顯示 `›` 分隔，窄螢幕（< 576px）隱藏以節省空間；太長時在導覽列內橫向捲動並預設捲到最右邊，不會把整個頁面撐寬
- 導覽列右側有專用的搜尋圖示按鈕（不再是「點麵包屑空白處」進搜尋，避免點歪誤開搜尋框）；窄螢幕（< 576px）隱藏「WhatSearch」標題，把空間留給路徑

### 會員與登入
- 本地帳密登入/註冊（不依賴 Line 或其他第三方服務）
- 密碼以 PBKDF2 雜湊儲存；支援明碼過渡機制，可直接編輯 `users.json` 填入明碼密碼，該帳號下次登入時會自動轉存為雜湊
- 第一個註冊的帳號自動成為管理者並啟用；後續帳號需管理者到 `/admin` 頁面手動啟用
- 瀏覽、搜尋完全公開不需登入；只有要播放 MP3/影片時才需要登入
- 登入、登出都會導回原本瀏覽的頁面；未登入時點音樂/影片會先導去登入，登入成功後自動接續播放原本點擊的項目

### 媒體播放
- 音樂：頁面內建播放器，含進度條（可拖曳跳轉當前秒數）；點任一首即從該首開始，依目前清單順序播放；清單上方有「自動下一首」（預設勾）與「播完重頭開始」（預設不勾）兩個選項，設定會記在瀏覽器
- 音樂會顯示 ID3 tag 資訊（歌手/專輯），讀不到就不顯示。**標籤的中日文編碼會自動修正**：很多中文 MP3 把 Big5／GBK／Shift-JIS（或 UTF-8）的位元組直接放在標示為 Latin-1 的欄位（ID3v1 一律如此），一般讀法會變成 `·R±¡Âà²¾` 這種亂碼。伺服器讀出歌名、演出者、專輯、專輯演出者後，把同一首歌的欄位一起偵測編碼（Latin-1 是無損的，可還原成原始位元組再重新解碼），並要求整體有夠高比例的雙位元組落在常用字區、解出的漢字不緊貼英文字母，所以 `Björk`、`Åge`、`Café` 這類歐洲語系 Latin-1 文字不會被誤判；本來就正確的字串（UTF-16、UTF-8 標籤）完全不動。限制：Big5 與 GBK 的範圍重疊，只能用啟發式判斷，標籤只有一個很短的欄位（例如只有 1～2 個字的歌名、沒有演出者與專輯）時簡體可能判成繁體；標籤讀取結果會快取 12 小時，修正後要重啟才會立刻看到
- **回到播放中**：播放音樂時可以隨意瀏覽其他資料夾；漢堡選單的「回到播放中」（正在播放、而且**已經離開**那首歌所在的資料夾時才會出現）會跳到正在播放那首歌所在的資料夾，把那首選取並捲到畫面中間。正在播放列上沒有這個按鈕，避免誤觸。從搜尋、最近上傳、我的最愛播放的歌曲也是跳到它真正所在的資料夾。資料夾 id 是路徑的 Base64，所以直接由播放中歌曲的 id 推出資料夾，不需要另外記錄。離開資料夾再回來時，播放中那首也會重新標示（以前聲音還在播、列上的標示卻會消失）；瀏覽器的「上一頁」可以回到剛才看的資料夾
- 手機鎖屏/控制中心整合（Media Session）：顯示歌名、歌手、專輯，可操作播放/暫停/上一首/下一首/拖曳進度；封面取自同資料夾的 `cover.jpg|jpeg|png` 或 `folder.jpg|jpeg|png`（不分大小寫），沒有就用站台 icon；搜尋/最近上傳這類跨資料夾清單不顯示封面
- 影片：頁面內疊層播放（非開新分頁）；播完會停下來，畫面上出現「播放下一部」讓你手動接續，不會自動跳下一部
  - 會記住每部影片看到哪（存在瀏覽器），下次點開自動從上次位置繼續；看超過 90% 或播完視為已看
  - 外掛字幕：影片同資料夾、同主檔名的 `.srt`／`.vtt`／`.ass`／`.ssa` 會自動掛成字幕軌（檔名可在主檔名後加語言標記，如 `01.zh-TW.srt`、`01.chs.ass`、`01.en.vtt`，支援 `zh-TW/cht/tc`、`zh-CN/chs/sc`、`en`、`ja` 等），可用疊層上方的「字幕」下拉選單（含「關閉」）或播放器原生的字幕選單切換，兩邊會同步；有繁體時預設繁體，會記住上次的選擇（含關閉）。不是 UTF-8 的字幕（含 BOM 的 UTF-16 例外）預設當 Big5 解碼；`.ass` 只取對話文字，樣式/特效一律忽略，但會依 `\an` 與樣式的 Alignment 決定置底/置中/置頂；搜尋、最近上傳等跨資料夾清單不支援。字幕不需要加進 `playtypes`。字幕樣式為白字黑色描邊、粗體、無底框，底部字幕使用瀏覽器預設的最低位置（iPhone 的原生全螢幕播放器會改用系統的字幕設定，不受影響）
  - MKV 內嵌字幕：播放 `.mkv`（需在 `playtypes` 加入 `.mkv`，且瀏覽器本身要能播放該檔案）時，伺服器以純 C# 解析 MKV，把內嵌的**文字字幕軌**（`S_TEXT/UTF8`、`S_TEXT/ASS`、`S_TEXT/SSA`）加進字幕選單，標示為「（內嵌）」；選到某一軌才會解析並轉成 WebVTT（結果在伺服器記憶體快取 30 分鐘）。圖片字幕（PGS、VobSub）不支援。不需要 ffmpeg
  - 播放速度（0.75x ~ 2x，會記住）；桌機快捷鍵：空白鍵暫停/播放、←/→ 倒退/快轉 10 秒、F 全螢幕、ESC 關閉
  - 播放失敗會在影片區顯示原因與「下載檔案」：伺服器未開放該類型（未在 `playtypes`）、瀏覽器不支援該容器/編碼（如 MKV、H.265、10-bit）、解碼失敗、網路中斷；播放中登入過期則導去登入頁，登入後自動接續。目前偵測不到「有畫面但沒聲音」（如瀏覽器不支援的音訊編碼）
  - iPhone 上用 `playsinline`，留在疊層內播放，不會跳去系統全螢幕播放器
- 影片資料夾（沒有子資料夾、沒有音樂，影片 ≥ 2 部，或剛好 1 部且長度 < 30 分鐘）自動切成追番畫面：每集一顆按鈕（01 02 03…，集數由檔名解析，解析不到就依排序編號），顯示作品名、集數、畫質與已看數，按鈕以顏色區分未看/看到一半（含進度底色）/已看；封面依序取：`cover.*`／`folder.*` → 第 1 集 MP4 內嵌封面（`covr`）→ 從第 1 集擷取一張畫面；可切回一般列表檢視；因為標題已顯示資料夾名稱，上方麵包屑在這個畫面不重複顯示最後一層
  - 資料夾只有 1 部影片（沒有子資料夾、沒有音樂）且找得到封面（`cover.*`／`folder.*` 或 MP4 內嵌封面）時，列表上方顯示封面、檔名、已看狀態與「播放」按鈕；找不到封面就維持一般列表
  - 影片播放時手機鎖屏/控制中心同樣會顯示標題與封面（追番模式為「集數 · 作品名」＋畫質），可操作播放/暫停/上一集/下一集/拖曳進度；單獨影片的封面取自 MP4 內嵌封面
- 音樂資料夾（沒有子資料夾、沒有影片，音樂 ≥ 3 首）自動切成專輯版面：上方是封面（`cover.*`／`folder.*`，沒有就取第 1 首的內嵌封面）、專輯名稱、演出者、「N 首 · 總長 · 年份」、「▶ 播放」鈕與「自動下一首／播完重頭開始」勾選；下方是歌曲列（曲序、歌名、長度，正在播放的那一列有醒目樣式）。曲序依序採用 ID3 音軌編號 → 檔名開頭數字（01_、02 、1.）→ 原本順序；歌名優先用 ID3 標題，沒有就用去掉副檔名與前置編號的檔名。超過 6 成歌曲的 ID3 專輯名稱相同時為「專輯模式」（標題用專輯名稱；合輯顯示「多位演出者」與每首演出者），否則為「歌單模式」（標題用資料夾名稱）。麵包屑隱藏最後一層，可切回一般列表檢視。播放佇列、鎖屏控制與封面都沿用這個順序與封面
  - 多片裝專輯也適用：子資料夾（扣掉 `Scans`／`Artwork`／`Booklet`）全部是光碟資料夾且至少 2 個、母資料夾沒有影片或音樂檔、各光碟合計 ≥ 3 首時，母資料夾直接顯示整張專輯，歌曲列依光碟分區（「Disc 1 · 12 首 · 48:30」），曲序各片自己從 1 開始、播放佇列跨光碟連續。光碟資料夾名稱不分大小寫，支援 `Disc 1`、`Disk2`、`CD1`、`CD 2`、`DVD1`、`碟1`、`第2碟`，後面可接說明（如 `Disc 1 - 白天`）；專輯名稱會先去掉 `(Disc 1)`、`[CD2]` 之類的後綴再統計。各光碟的歌曲由伺服器隨 `/api/folder` 一併回傳（`discs`），畫面第一次渲染就是最終版面；音樂標籤依「路徑＋大小＋修改時間」快取，重複進入不用再開檔
- 圖片：Lightbox 疊層預覽，可用左右鍵或箭頭按鈕切換上一張/下一張
- 文字檔（`.md`/`.txt`）：疊層預覽，`.md` 用 Markdig 轉成 HTML 顯示、`.txt` 純文字顯示；編碼會自動偵測（UTF-8、UTF-16 BOM、Big5、GBK、Shift-JIS），例如 cmd 的 `dir /b` 結果（Big5）也能正確顯示。Big5 與 GBK 的有效範圍重疊，只能用啟發式判斷，很短的檔案可能判錯（外掛字幕也用同一套偵測）
- 正在播放/播放中的項目會標示選取樣式，方便在長列表中定位

### 資料夾排序
- 一般資料夾的列表（項目至少 6 個）上方有排序選單：預設（維持伺服器給的順序，也就是檔案系統的順序）／名稱 A→Z（數字依大小，`2` 排在 `10` 前面）／時間 新→舊、舊→新（修改時間）；可評分的季資料夾列表另有評分 高→低、低→高（沒有「大小」排序：資料夾沒有大小，檔案大小也用不到）。**資料夾永遠排在檔案前面**，同值的維持原順序，沒有該欄位的（例如沒評分）排在後面
- **依資料夾各自記憶**：選擇存在這個瀏覽器（`localStorage` 的 `sortPrefs`，最多記 300 個資料夾），下次進同一個資料夾就是上次的排序；不同裝置各記各的，資料夾改名後（id 是路徑編碼）記憶就失效。選過排序的資料夾即使不足 6 個項目也會繼續顯示選單
- 不套用在：專輯版面（依曲序）、追番畫面（依集數）、搜尋/最近上傳/我的最愛這類跨資料夾的清單；但在專輯或追番資料夾切到「列表檢視」時，列表可以排序。播放佇列依畫面上的順序
- 舊版（1.9.x）評分列表的排序是整個瀏覽器共用一個值，升級後在還沒個別選過的評分列表會先沿用它

### 我的最愛（需登入）
- 專輯版面的標頭有「收藏」鈕（收藏的是整個資料夾，多片裝專輯收藏母資料夾）；每首歌的右側、列表檢視與搜尋/最近上傳裡的音樂列、以及畫面底下「正在播放」列都有愛心，可收藏單曲，三處的狀態同步。沒登入時不顯示愛心與入口
- 導覽列選單「我的最愛」分成「專輯」與「單曲」兩個分頁（括號內是數量，會記住上次停留的分頁）：專輯分頁依最近收藏排序，點進去就是該資料夾；單曲分頁依收藏順序，每列顯示所在資料夾。點任一首歌就會以目前分頁的歌曲為播放佇列，跨專輯連續播放，等於一份自己挑的虛擬精選歌單；「自動下一首／播完重頭開始」照常有效。在這個畫面取消收藏，該列會留著（愛心變空心），方便按錯時再點一次，重新進入才會消失
- 資料存在伺服器，**依會員分開**：`data/userData/favorites.json`（格式 `{ 會員名稱: { albums: [id…], tracks: [id…] } }`，存的是資料夾/檔案 id，不複製標籤；已加入 `.gitignore`），手機與桌機用同一個帳號就同步
- 被改名、移走或刪除而找不到的項目不會列出，但資料保留（檔案回來就會再出現），清單下方會提示「另有 N 筆找不到」。收藏不存在的項目會被伺服器拒絕
- API：`GET /api/favorites`（id 清單，用來標示愛心）、`POST /api/favorites`（`{kind: "album"|"track", id, fav}`）、`GET /api/favorites/items`（解析後的清單）；都需登入，未登入回 401
- **音量平衡（只在「單曲」分頁播放時套用）**：跨專輯的歌曲原本音量不一，連播很不舒服，所以單曲分頁上方有「音量平衡」勾選（預設開、會記住），把每首歌調到同一個響度。
  - 伺服器用純 C#（NLayer 解碼 MP3 + ITU-R BS.1770-4 / EBU R128 響度量測，K 加權、400ms 區塊、-70 LUFS 絕對閘門與 -10 LU 相對閘門）在背景分析「被收藏的單曲」，單一低優先權執行緒依序處理，不影響瀏覽；收藏當下就排入，通常進清單時已算好。結果依「路徑＋大小＋修改時間」存在 `data/loudness.json`（已加入 `.gitignore`），檔案改了才重算。單聲道視為兩聲道播同一份。不需要 foobar2000／ReplayGain 標籤，也不會修改你的音樂檔
  - 調整量 = 目標響度 − 該首響度（LUFS）。目標預設 -14 LUFS（與主流串流平台相同，數字越接近 0 整體越大聲）；調高時受峰值限制（加完最高 -1 dBFS，避免爆音，峰值已很高的歌維持原音量），並限制在 +12 / -20 dB 內。想調整可在 `config.local.json` 加 `"loudness": { "target": -16, "maxBoostDb": 12, "maxCutDb": 20 }`
  - 每首歌下方會顯示量測到的 LUFS 與調整量（例如 `-16.3 LUFS · 調整 +2.3 dB`），方便和 foobar2000 等工具的結果對照；分析中會顯示「分析音量中…」並自動更新。**只支援 MP3**，其他格式或損毀檔案會標示原因並維持原音量
  - 前端用 Web Audio 的 `GainNode` 套用（所以可升可降，iPhone 也有效），只有從單曲分頁開始播放時才建立，其他地方的播放完全不經過 Web Audio。暫停前會先把音量在約 30ms 內降到 0 再暫停、繼續時還原。已在 iPhone（iOS 18、Safari）實測：增益有效、鎖屏續播與自動接下一首、鎖屏控制、切換 App 都正常
  - 專輯增益（整張專輯用同一個調整量、保留曲間強弱）目前不做；專輯頁、搜尋與「最近上傳」的播放都維持原音量

### 新上架通知（站內，需登入）
- 有新動畫、新集數、新專輯時，**漢堡按鈕右上角出現紅色未讀數字**，選單多一個「新上架」（也帶數字）；點進去是「新上架」頁：依今天／昨天／日期分組，每筆是一部動畫或一張專輯（`新作品 · 2 集`、`新增 1 集`、`新專輯`），點一筆就進到該資料夾。**打開這一頁就視為全部已讀**（數字歸零），但這次進來時還沒讀的那幾筆仍有紅點，離開後下次就沒有了。已讀記在伺服器、依會員各自一份，手機與桌機同步；新會員第一次不會把過去的全部當成未讀。列表與動畫頁本身不加任何「新」標示
- **設定檔指定要通知哪些分享根與算法**（預設不啟用，沒設定就完全沒有入口與紅點）：

```json
"news": {
  "shares": [
    { "name": "Anime", "mode": "episodes", "depth": 2 },
    { "name": "Music", "mode": "albums",   "maxDepth": 4 }
  ],
  "scanMinutes": 120,
  "activeFrom": "08:00",
  "activeTo": "22:00",
  "stableMinutes": 5,
  "fullScanHours": 6
}
```

  - `name` 是分享根名稱（`folders` 的 `title`）。`episodes`（動畫）：作品資料夾位在分享根底下第 `depth` 層（`Anime6-4\作品` 為 2），出現新作品算「新作品」，既有作品資料夾裡多了新的影片檔算「新增 N 集」；12 小時內同一部陸續上架的合併成一筆。`albums`（音樂）：**只有新的專輯資料夾出現才算**，之後補進歌曲不算；專輯資料夾自動辨認，所以 `Music\專輯`、`Music\歌手\專輯` 混著放都可以（最多往下找 `maxDepth` 層）：直接放著音樂檔的資料夾是一張專輯，多片裝（`Disc 1`、`CD2`…至少 2 個且有音樂）以母資料夾為一張，`Scans`／`Artwork`／`Booklet` 略過
  - **多久掃一次、什麼時候掃**：`scanMinutes` 是預設間隔（預設 120 分鐘），每個分享根可以在自己那一段寫 `"scanMinutes": 30` 覆蓋；`activeFrom`／`activeTo`（本機時間 `HH:mm`，預設 08:00–22:00）以外的時段**完全不掃描**，到了時段開始才掃（兩個都留空表示不限時段；可以跨午夜，例如 22:00–06:00）。啟動後約 30 秒掃第一次；第一次（建立基準）不受時段限制
  - **偵測方式**：背景定時掃描加快照比對（網路磁碟上的檔案監看不可靠），以「系統第一次看到」的時間為準；檔案（或專輯）大小要連續 `stableMinutes` 分鐘不變才算上架，所以複製、下載到一半不會通知，`.part`、`.!qB`、`.crdownload` 等暫存檔與非影片／音樂檔也不算。掃描間隔拉長之後，看到新項目時**不必等滿一個間隔**：穩定時間一過（約 `stableMinutes` 加 5 秒）就會提早複查一次再通知。從檔案出現到紅點出現，最久約是「掃描間隔 + 穩定時間」
  - **第一次啟用先建立基準**：現有的全部視為已知，不會一啟用就通知整個資料庫。分享根暫時連不上（網路磁碟斷線）時這輪掃描直接略過、不動快照，恢復後不會誤報
  - **怎麼省 I/O（Music 檔案多、在網路磁碟上時很重要）**：每個資料夾只做一次查詢（同時取子資料夾與檔案）；`albums` 已通知過的專輯當成葉節點，資料夾修改時間沒變就整個略過，不列出裡面的內容（實測 25 位歌手 × 4 張專輯：基準掃描 126 次查詢，之後每輪約 26 次，不到 1/4，其中 100 張專輯被略過）；`episodes` 對每個作品資料夾「本身」重新讀一次修改時間，沒變且沒有等待確認的檔案就不列出裡面的檔案。資料夾修改時間不會往上一層傳，而且**在 NTFS 上從父資料夾列表拿到的子資料夾日期會過期**（實測舊了一個多月），所以動畫模式一定要對資料夾本身重新讀取；另外每 `fullScanHours` 小時（預設 6）做一次完整掃描（不看修改時間）當保險
  - **怎麼知道掃一次要多久**：每輪掃描結束都會在日誌寫一行（Info，主控台與日誌檔都看得到），日誌檔在執行目錄的 `logs
log-日期.all.log`，搜尋「**新上架掃描**」，例如：`新上架掃描 Music(albums)：耗時 13ms，查詢 26 個資料夾，略過 100 個沒變動的專輯，新增 0 筆通知`。「完整掃描」的那輪（第一次與每 `fullScanHours` 小時）會是最久的一輪；時段外會寫「目前不在掃描時段內，下一次 …」。如果 Music 的完整掃描在網路磁碟上太久，可以把 `fullScanHours` 調長，或把 Music 的 `scanMinutes` 調長
  - 資料存在 `data/news.json`（事件，保留最近 300 筆／90 天）、`data/news-state.json`（掃描快照）、`data/userData/news-read.json`（每個會員的已讀時間），都已加入 `.gitignore`。限制：資料夾或檔案改名、搬位置會被當成新的
  - API：`GET /api/news`（清單）、`POST /api/news/read`（標示已讀），未讀數併在 `GET /api/info` 的 `news` 欄位（未登入或未啟用為 null）

### 動畫評分（追番用，系統共用一份）
- 在 `config.local.json` 指定哪裡的資料夾可評分（預設不啟用）：`"rating": { "shares": ["Anime"], "depth": 2 }`。`shares` 是分享根的名稱（`folders` 裡的 `title`），`depth` 是動畫資料夾位在分享根底下第幾層：`Anime6-4\作品名稱` 是第 2 層，只有這一層的資料夾有評分；`2026-4` 本身、Music、Movie 等其他地方都不會出現星星
- **評分記在系統裡，不改資料夾名稱**（`data/ratings.json`，已加入 `.gitignore`；格式 `{ 名稱: 評分 }`）。因為資料夾 id 是路徑編碼，改名會讓續播進度、我的最愛的資料夾收藏、書籤對不上，所以不用改名的方式。key 是「去掉結尾星等、空白收斂後的名稱」，動畫搬到別的資料夾評分仍然跟著走；`FX 戰士久留美` 與 `FX 戰士久留美[Eng]` 名稱不同，各自一份
- 評分 2.5～5，以 0.5 為單位（2 星以下的作品直接刪掉，不評分，所以不提供）：星星只負責顯示，點星星（含旁邊的分數）會彈出評分面板（手機是貼在畫面底部的面板，寬螢幕的桌機、平板改成置中的對話框；桌機可按 Enter 確定、Esc 取消），上面是 `2.5 3 3.5 4 4.5 5` 六顆大按鈕，下面是「清除評分」「取消」「確定」。**點分數只是選擇，上方的星星預覽會跟著變（並標示「尚未儲存」），按「確定」才會儲存**；「清除評分」也是先選成未評分、再按確定。這樣不會因為星星太小而點錯或分不清半顆整顆，點錯了或不想改，按取消、點旁邊空白或 ESC 就離開，不會動到原本的分數。需要登入才能評分，未登入看得到星星但點了會導去登入
- **沿用既有的名稱星等**：系統裡還沒有評分時，讀資料夾名稱結尾的 `(★★★☆)`（★ 算 1，結尾的 ☆ 算 0.5；全形括號也可以）當作評分，所以原本手工標好的不用重打；一旦在網頁上評過，就以系統記錄為準（包含明確設為未評分）。畫面上的名稱一律去掉結尾星等，避免和星星對不上，列表、動畫頁標題與麵包屑都是
- 季資料夾列表：每部動畫的最後一行（左邊是修改時間，去掉秒數；右邊是星星，縮小成 80%、間距再縮小約 1/3，離標題最遠，減少進入資料夾時的誤觸）顯示星星，列表上不顯示分數數字（半顆星看星形、未評分是全灰的星星；數字在動畫頁最上方的「我的評分」與評分面板裡看得到）；上方同一行有排序（見「資料夾排序」，另有評分 高→低、低→高）、篩選（全部／4 星↑／3.5 星↑／未評分）與「複製」鈕，未評分的永遠排在最後。動畫頁（追番畫面或列表檢視）最上方有「我的評分」
- **複製**：季列表的「複製清單」會把目前畫面（含排序與篩選）複製成純文字，第一行是說明（`2026-4 動畫評分清單（滿分 5 分，以 0.5 為單位；未評分表示還沒打分）`），之後每行「名稱：評分」，格式簡單，方便貼給語言模型再做分析；動畫頁的「複製」複製單部。站台常是 HTTP（瀏覽器的一鍵複製 API 只在 HTTPS 可用），所以用「選取＋複製指令」，萬一仍失敗會跳出已全選的文字框讓你手動複製

### 設定檔
- `config.json` 是專案的預設值（進版控）。各台機器自己的設定（分享資料夾路徑、`playtypes` 等）寫在同資料夾的 `config.local.json`，**不進版控**（已在 `.gitignore`），`git pull` 就不會再因為改過設定而衝突
- 啟動時 `config.local.json` 疊加在 `config.json` 上：物件逐項合併、陣列（如 `playtypes`、`folders`）與單一值整個取代、鍵名不分大小寫，兩個檔案都可以寫註解與結尾逗號。所以本機檔只需要寫你要改的項目，上游新增的設定會自動拿到預設值
- 沒有 `config.local.json` 時只讀 `config.json`；本機檔格式錯誤時會在主控台提示並忽略，不影響啟動
- 本機檔放在專案資料夾，編譯時會複製到執行檔旁邊；之後如果刪除專案裡的本機檔，也要一併刪除執行檔旁（`bin` 底下）複製過去的那份

### 播放診斷（手機一直轉圈圈時用）
- **伺服端日誌**：`/get/` 的影音請求都會記錄，寫在執行目錄下的 `logs/nlog-日期.all.log`（日誌資料夾已被 `.gitignore` 忽略），內容有來源 IP、裝置（如 `iPhone iOS17.2/Safari`、`Android/Chrome`）、`Range`、狀態碼、傳送長度、耗時、是否被客戶端中止（`ABORTED`）與傳輸速度（`rate=`）。一般請求只寫進檔案；**主控台只顯示異常**：狀態碼 3xx/4xx/5xx（例如未登入被導去登入頁的 302）、錯誤、傳輸速度低於 3Mbps 的大檔案
- iPhone Safari 播放時會先送 `Range: bytes=0-1` 探測，之後才請求實際範圍；使用者拖曳或暫停時請求被中止（`ABORTED`）是正常的
- **前端卡住提示**：影片載入或緩衝超過 8 秒仍沒開始播放，影片區上方會顯示黃字提示（已緩衝秒數、影片平均位元率、目前實際下載速度的估算；iPhone 上播 MKV 會提醒不支援），可點右上角關閉
- **自動回報**：卡住或播放錯誤時，瀏覽器會把當下狀態（`readyState`、緩衝、估算速度、是否支援 H.264/HEVC 等）回報到伺服端日誌（`clientdiag` 開頭），30 秒內最多一次，所以不用拿著手機看畫面，也能在伺服器的日誌看到手機端的情況

### 找不到資料夾（改名後的舊網址）
- 資料夾被改名或移走後，舊網址／書籤不再是空白頁，會顯示「找不到這個資料夾」：列出要求的路徑、麵包屑顯示到最近還存在的上層，並提供「回到上一層」與「回到上次看的資料夾」
- 會在**同一層**的資料夾裡依名稱相似度建議「你是不是要找」：只差空白或大小寫、去掉括號註記後相同（`作品` → `作品 (2026)`、`作品 (★★★☆)` → `作品 (★★★★)`）、其中一個名稱包含另一個、或編輯距離很近（`2026-4` → `2026-04`）；改得差異太大就不建議。如果是中間某一層被改名，且原本路徑後面的子層在建議的資料夾底下仍存在，會一併帶到完整的新路徑。分享根名稱打錯也會建議
- 載入資料夾時伺服器出錯或網路失敗，會顯示錯誤與「重試」，不再留下空白頁
- 這是「找不到時給建議」，不是自動轉址；舊書籤的網址本身不會被更新
